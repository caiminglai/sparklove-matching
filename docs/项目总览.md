## 1. 项目定位

精准匹配是一个基于 Web 的相亲匹配平台，本质是：
> 给一个人贴很多标签 -> 按特定标签筛选 -> 相当于线上 Excel 表格

核心功能：
- 发布信息（贴标签）
- 按标签筛选搜索
- 管理后台查看用户列表
- 举报功能（看评语决定怎么处理）
- 保证金机制（确保双方见面信息正确）

不需要的功能：
- 站内消息/聊天（不是社交软件）

需要但保持最小实现的功能：
- 支付/保证金凭证（微信、支付宝下单与回调已实现，用途是缴纳保证金与解锁联系方式，不是独立电商支付系统）

## 4. 启动方式

方式 1（推荐）：Docker Compose
```bash
cd E:\website                 # 编排文件 docker-compose.yml 所在目录
docker compose up -d postgres jzxr jzxr-web
```
启动后：前端 `http://localhost:4000`、后端 `http://localhost:8080`、PostgreSQL 宿主端口 `5433`。

方式 2：手动启动（不走 Docker 时）
```bash
# 后端（终端1）
cd E:\website\2.my-two-website\backend
npm start

# 前端（终端2）
cd E:\website\2.my-two-website\app
npm run dev
```

> 旧的"双击 `E:\website\start-all.bat`"已失效：该路径下没有这个文件，实际脚本是 `E:\website\5.共享脚本\启动所有网站.bat`。
> 该脚本内容仍是逐目录 `npm start` / `npm run dev` 的裸机写法，**当 Docker 容器已占用 3000 / 8080 / 4000 时会端口冲突，已过期**，优先用方式 1。

## 5. 管理后台

- 地址：http://localhost:8080/admin
- 密码：查看 `backend/.env` 中的 `ADMIN_PASSWORD`

> ⚠️ 已知缺口（上线前必须处理）：容器方案下 `/admin` 公网不可达——前端容器只转发 `/api/`、`/uploads/`、`/avatars/`，Caddy 只反代 `jzxr-web:80`，宿主 `8080` 又只绑 `127.0.0.1`。解法二选一：Caddyfile 加 `域名/admin → reverse_proxy jzxr:8080` 并加 `basic_auth`，或运维时走 SSH 隧道 / 宿主机回环 `127.0.0.1:8080/admin`。详见 `docs/部署运维.md` §3。

## 6. 环境变量

后端（`backend/.env`，只列变量名；容器内这些值由 `docker-compose.yml` 的 `environment` 注入，详见 `docs/部署运维.md` §8）
```env
PORT
API_PREFIX
FRONTEND_URL
SERVER_ORIGIN
ADMIN_USERNAME
ADMIN_PASSWORD        # 必填
TOKEN_SECRET          # 必填：db/index.js:108-117 生产缺失直接 throw
ENCRYPTION_KEY        # 必填：同上
PG_HOST               # 容器内必须是服务名 postgres，不是 localhost
PG_PORT
PG_DATABASE
PG_PASSWORD           # 必填
EMBEDDING_PROVIDER
EMBEDDING_API_URL
EMBEDDING_API_KEY
EMBEDDING_MODEL
```
> `NODE_ENV` 只能由进程环境（shell 或 compose 的 `environment`）决定，**不要写在 `backend/.env` 里**：
> - `server.js:3` 在调用 `dotenv.config()` **之前**就读了 `process.env.NODE_ENV` 来决定加载 `.env` 还是 `.env.production`，所以写在 `.env` 里改不了加载路径（仓库里也没有 `.env.production`，只有 `.env` 和 `.env.example`）。
> - 但它会在 dotenv 载入后生效，把 `db/index.js:7` 的 `_isProd` 置为 true，进入生产分支：`TOKEN_SECRET` / `ENCRYPTION_KEY` 缺失时直接 throw（`db/index.js:108-117`），本地会起不来。
> 容器方案由 `docker-compose.yml:60` 注入 `NODE_ENV=development`，需要生产模式时改这一处，不要往 env 文件里加。

前端（`app/.env.development`）实际只声明 `VITE_BASE_URL` 一个变量。
`VITE_API_BASE_URL` 已从开发环境刻意删除——开发模式下 `src/api/config.ts` 直连 `http://localhost:8080/api`。

生产（`app/.env.production`）声明 `VITE_BASE_PATH` 与 `VITE_API_BASE_URL`。

生产环境必须检查 `app/.env.production` 中 `VITE_BASE_PATH` 设置（`vite.config.ts` 读的是这个名字，不是 `VITE_BASE_URL`）。

## 10. 数据库概览

数据库：PostgreSQL 18 + pgvector v0.8.2
数据位置：PostgreSQL 跑在 `postgres` 容器内，数据在 Docker 命名卷 `pgdata`（容器挂 `/var/lib/postgresql`）。仓库 `data/` 只存 SQL 种子/导出文件、不含运行数据，且这些 SQL **不在 Git 里**，上服务器必须单独 scp。

### 10.1 核心业务表

| 表名 | 用途 |
|------|------|
| `auth_users` | 用户认证（手机号、密码哈希） |
| `users` | 用户资料（40+ 字段） |
| `user_ratings` | 用户评价 |
| `user_reports` | 用户举报 |
| `contact_unlocks` | 联系方式解锁记录 |
| `deposits` | 保证金记录 |
| `payment_orders` | 支付订单 |
| `admin_settings` | 管理设置 |
| `admin_logs` | 管理员操作日志 |

> 上表只列常用核心表。全库共 **14 张表**（另有 `user_custom_fields`、`field_mappings`、`custom_filters`、`"数据库映射表"` 4 张 + §10.2 的 `user_vectors`），完整清单见 `docs/架构与API.md` §4.1。

### 10.2 向量数据库表（pgvector）

| 表名 | 用途 |
|------|------|
| `user_vectors` | 用户画像向量表（HNSW 索引，余弦相似度） |

**向量表结构说明：**
- `profile_vector`：用户资料向量（1536 维，text-embedding-ada-002）
- `expectation_vector`：择偶要求向量（1536 维）
- 索引类型：HNSW（Hierarchical Navigable Small World）
- 距离度量：vector_cosine_ops（余弦相似度）
- 相似度计算：`1 - (vector_a <=> vector_b)`
