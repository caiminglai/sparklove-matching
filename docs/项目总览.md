## 1. 项目定位

精准匹配是一个基于 Web 的标签找人平台，本质是：
> 给一个人贴很多标签 -> 按特定标签筛选 -> 相当于线上 Excel 表格

核心功能：
- 发布信息（贴标签）
- 按标签筛选搜索
- 管理后台查看用户列表
- 举报功能（看评语决定怎么处理）
- 诚意认证费（一次性服务费，覆盖资料人工核验，支付后不退）

> 上面这五条各自在线上跑到什么程度（哪条从没跑过、哪条靠代录），一律看 §9 最后一列，别把这张清单当验收结论。

不需要的功能：
- 站内消息/聊天（不是社交软件）

需要但保持最小实现的功能：
- 支付/认证费凭证（微信、支付宝下单与回调已实现，用途是缴纳诚意认证费与解锁联系方式，不是独立电商支付系统）

## 4. 启动方式

方式 1（推荐）：Docker Compose
```bash
cd E:\website                 # 编排文件 docker-compose.yml 所在目录
docker compose up -d postgres jzxr jzxr-web
```
启动后：前端 `http://localhost:4000`、后端 `http://localhost:8080`、PostgreSQL 宿主端口 `5433`。

方式 2：手动启动（不走 Docker 时）
```bash
# 后端（终端1）
cd E:\website\sparklove-matching\backend
npm start

# 后端门禁（改完后端必跑，CI 的 Backend job 就是这三条）
cd E:\website\sparklove-matching\backend
npm run format:check && npm run lint && npm test

# 前端（终端2）
cd E:\website\sparklove-matching\app
npm run dev
```

> 旧的"双击 `E:\website\start-all.bat`"已失效：该路径下没有这个文件。**10-14 再补一刀**：这里原来写的第二个落点 `E:\website\5.共享脚本\启动所有网站.bat` **盘上同样查无**（`ls -d /e/website/5.共享脚本` ＝ No such file or directory）⇒ 本机启站只走本文档的容器命令，别再找任何 .bat。

## 6. 环境变量

后端（`backend/.env`，只列变量名；容器内这些值由 `docker-compose.yml` 的 `environment` 注入，详见 `docs/部署运维.md` §8）
```env
PORT
API_PREFIX
FRONTEND_URL
SERVER_ORIGIN
ADMIN_USERNAME
ADMIN_PASSWORD        # 必填
TOKEN_SECRET          # 必填：db/index.js:108-117 生产缺失直接 throw
ENCRYPTION_KEY        # 必填：同上
PG_HOST               # 容器内必须是服务名 postgres，不是 localhost
PG_PORT
PG_DATABASE
PG_PASSWORD           # 必填
EMBEDDING_PROVIDER
EMBEDDING_API_URL
EMBEDDING_API_KEY
EMBEDDING_MODEL
```
> `NODE_ENV` 只能由进程环境（shell 或 compose 的 `environment`）决定，**不要写在 `backend/.env` 里**：
> - `config/index.js:18` 在调用 `dotenv.config()`（同文件 :19）**之前**就读了 `process.env.NODE_ENV` 来决定加载 `.env` 还是 `.env.production`，所以写在 `.env` 里改不了加载路径（仓库里也没有 `.env.production`，只有 `.env` 和 `.env.example`）。10-30 起这段从 `server.js` 顶部搬进了 `config/index.js`，`server.js:19` 第一行 require 的就是它——搬的是位置，不是顺序。
> - 但它会在 dotenv 载入后生效，把 `db/index.js:7` 的 `_isProd` 置为 true，进入生产分支：`TOKEN_SECRET` / `ENCRYPTION_KEY` 缺失时直接 throw（`db/index.js:108-117`），本地会起不来。
> 容器方案由 `docker-compose.yml:74` 注入 `NODE_ENV=development`（10-14 现量：:74 才是 `- NODE_ENV=development`，旧写的 :60 是站1 那段的 `- local-net`），需要生产模式时改这一处，不要往 env 文件里加。

前端（`app/.env.development`）实际只声明 `VITE_BASE_URL` 一个变量。
`VITE_API_BASE_URL` 已从开发环境刻意删除——开发模式下 `src/api/config.ts` 直连 `http://localhost:8080/api`。

生产（`app/.env.production`）声明 `VITE_BASE_PATH` 与 `VITE_API_BASE_URL`。

生产环境必须检查 `app/.env.production` 中 `VITE_BASE_PATH` 设置（`vite.config.ts` 读的是这个名字，不是 `VITE_BASE_URL`）。

## 10. 数据库概览

数据库：PostgreSQL 18.6 ＋ pgvector 0.8.6（2026-10-14 线上现量）
数据位置：PostgreSQL 跑在 `postgres` 容器内（镜像 `pgvector/pgvector:pg18`），数据在 Docker 命名卷——compose 里叫 `pgdata`，Docker 实际卷名 = `www_pgdata`（容器挂 `/var/lib/postgresql`）。仓库 `data/` 只存 SQL 种子/导出文件、不含运行数据，且这些 SQL **不在 Git 里**，上服务器必须单独 scp。

### 10.1 核心业务表

| 表名 | 用途 |
|------|------|
| `auth_users` | 用户认证（手机号、密码哈希） |
| `users` | 用户资料（40+ 字段） |
| `user_ratings` | 用户评价 |
| `user_reports` | 用户举报 |
| `contact_unlocks` | 联系方式解锁记录（`method='pack'`＝次数包扣的次数） |
| `deposits` | 认证费记录（表名沿用 deposits） |
| `payment_orders` | 支付订单 |
| `admin_settings` | 管理设置 |
| `admin_logs` | 管理员操作日志 |

> 上表只列常用核心表。全库共 **14 张表**（另有 `user_custom_fields`、`field_mappings`、`custom_filters`、`"数据库映射表"` 4 张 + §10.2 的 `user_vectors`），完整清单见 `docs/架构与API.md` §4.1。

### 10.2 向量数据库表（pgvector）

| 表名 | 用途 |
|------|------|
| `user_vectors` | 用户画像向量表（HNSW 索引，余弦相似度） |

**向量表结构说明：**
- `profile_vector`：用户资料向量（1536 维，text-embedding-ada-002）
- `expectation_vector`：择偶要求向量（1536 维）
- 索引类型：HNSW（Hierarchical Navigable Small World）
- 距离度量：vector_cosine_ops（余弦相似度）
- 相似度计算：`1 - (vector_a <=> vector_b)`

> **这套东西今天没在用（2026-10-14 现量）。** 线上 `user_vectors` **0 行**；容器里 `EMBEDDING_PROVIDER=mock`、`EMBEDDING_API_KEY` 是占位值；前端没有任何页面调 `/api/vector/*`，首页那个「向量搜索」是个不带请求的角标。
> ⚠️ 要注意的一条：mock 分支**不报错**（`backend/services/vector.service.js:75-89` 拿字符串哈希拼一个假向量就返回），所以管理员要是点了 `POST /api/vector/batch`，库里会多出 99 行**看起来像向量**的数，之后的"相似用户"全是噪声。要启用：先配真 `EMBEDDING_API_KEY`（**花钱**），再小批量生成、抽一行核对相似度，别一上来打 batch。
