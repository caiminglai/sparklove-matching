## 3. 🔴 承重设置：compose 里 `NODE_ENV=development` 不许"顺手改成 production"

这不是漏改，是**承重**。链条三步，每一环都量过：

1. `docker-compose.yml:74` 给 `jzxr` 传 `NODE_ENV=development`；
2. `backend/server.js:3` 按它决定读哪个文件——`path.join(__dirname, process.env.NODE_ENV === 'production' ? '.env.production' : '.env')`；
3. compose 只把 `backend/.env` 挂进容器（`docker-compose.yml` 里 `jzxr` 的 `volumes:` 第一条 `../2.my-two-website/backend/.env:/app/.env:ro`）。

改成 `production` 后它去读**没挂载的** `.env.production` ⇒ 支付宝私钥、`EMBEDDING_*`、`FRONTEND_URL`、`ADMIN_PASSWORD` 全成空值。**症状最坑：容器正常起、页面正常打开，收款和向量检索静默失效。** 要真上 production 配置，得先把那个文件名也挂进容器再改这一行。

出处：公共仓 `CONVENTIONS.md:15`（四条铁律第 4 条）。

## 6. 换行符（Windows 开发者的头号脏提交来源）

规则：仓库内一律 **LF**；`*.bat`/`*.cmd` 保持 CRLF；`*.db`、图片、压缩包标 `binary`（本站 `.gitattributes` 第 15 行 `* text=auto eol=lf`、第 96 行 `*.db binary`）。

现量（`git ls-files --eol`，2026-10-25）：**136 个 `i/lf` ＋ 2 个 `i/-text`，`i/crlf` 与 `i/mixed` 均为 0**。那 2 个 `i/-text` 是 `app/public/alipay-qr.png` 与 `app/public/wechat-qr.png`（收款码，被 `.gitignore` 显式放行，本来就没有行尾概念）。归一那笔历史：站2 `b631e40`（22 个文件，纯换行符、单独一笔）。

四条尺子与坑：

1. **量 CR 只认两条**：`git ls-files --eol`（哪些文件含 CR）、`tr -dc '\r' | wc -c`（某一个文件里有几个）。🔴 `git grep --cached -l $'\r'` 是**坏探针**——实测它回的文件数正好等于文本文件总数（CR 在传参时被吃掉，等于空前缀匹配每一行）。凡"命中数 ≈ 总数"的探针先怀疑探针本身。
2. 提交前跑这两行，两个数不等说明编辑工具把整个文件的重写混进了 diff（**`git status` 干净不代表工作区等于仓库**）：
   ```bash
   printf "工作区CR=" && tr -dc '\r' < 文件 | wc -c
   printf "仓库CR  =" && git show HEAD:路径 | tr -dc '\r' | wc -c
   ```
3. `.gitattributes` 一放进仓，所有"仓库内容本身是 CRLF"的文件会立刻被报成整文件修改（内容和 HEAD 完全一致、`git diff --numstat` 仍写 1357 1357）。**看真实改动一律加 `--ignore-cr-at-eol`。**
4. 本机工作区那份带 CRLF 的文件被 `COPY` 进镜像 ⇒ **本机重建出来的字节数不能与服务器／公网的比大小**（本站 `app/` 烘在 `jzxr-web` 镜像里，同样吃这条）。要比就比 `git cat-file blob HEAD:路径 | md5sum`。

长期纪律：纯换行符提交必须**单独一笔**、且排在功能提交**之后**——混进功能提交里就再也 review 不动了。

## 7. 注释：写"为什么"，不写"做了什么"

- 每个后端文件顶部 3–6 行：这个文件管什么、对外暴露哪些路由/函数、动它要注意什么（依赖哪个鉴权中间件、有没有挂载顺序要求）。写不出有信息量的第三条就只写两条。
- 行内注释只在**约束不显而易见**处出现：绕过某个 bug、隐式不变量、时序要求。
- 现量（2026-10-25，口径 = `git ls-files backend` 里的 `.js`，读工作区内容，判据 = 文件内是否存在以 `//`、`/*`、`*` 开头的行）：`backend/` **40 个 `.js`，零注释 0 个**，注释行 **842 / 6,541 = 12.9%**。
  对照旧账：公共仓 `CONVENTIONS.md:190` 写的"35 个、8.4%"是 09-25 的数，已漂。
- 调试日志**不引入日志库**：用 ESLint `no-console`（`allow: ['warn','error']`）把裸 `console.log` 变成可见告警；维护脚本目录豁免（往 stdout 打东西是正当用途）。
- 浏览器里的调试把手（挂 `window.__xxx` 那种）一律用查询参数门控，默认不挂载。生产页面带 `console.log` 加一个人人可写的挂点，不是"方便排查"，是白送的攻击面。

## 8. 路由与接口的约定

- 路由参数名**一律英文**。Express 的 path-to-regexp 下中文参数名会 `keys=[]`，接口从写下那刻起就是死路由。
- SPA 兜底 `app.get('*')` 会把**任何没被显式挂载的路径伪装成 200 的 index.html**。⇒ 新路由必须注册在兜底之前；**验证接口要同时看 `Content-Type` 和字节数，只看状态码等于没验。**
- 公开只读接口只回字段白名单，禁止 `SELECT *`。
- **运行控制不开 HTTP 接口**：关停/重启只走 `SIGTERM`/`SIGINT` + `docker stop`/`restart`。（本站本来就没有 `/shutdown`。）
- **限流闸**：新增写入口必须挂同一把闸。现量（2026-10-25，`grep -n checkRateLimit` + `grep -n RateLimit backend/routes/auth.js`）**8 个调用点**：
